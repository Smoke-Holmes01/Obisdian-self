## 三、 第二部分：技术核心概念与架构基础（技术考察必问）

### Q5: “请用通俗的语言向业务方解释：什么是智能体（Agent）？它与我们常见的对话机器人（Chatbot）有什么本质区别？”
> **考查目的**：抽象概念降维表达能力、向跨部门沟通的能力。

* **核心回答要点**：
  * **传统 Chatbot（像顾问/咨询师）**：用户问一句，它根据已有记忆回答一句。**“只有嘴巴，没有手脚”**，不能替用户去干活，数据截止后不知道最新信息，遇到复杂任务只能给建议。
  * **智能体 Agent（像全能数字员工）**：用户给出一个模糊目标（如‘帮我整理上个月太原分公司的销售报表并找出异常数据发给财务’），Agent 拥有**大脑（会拆解步骤）、眼睛（能检索知识库）、手脚（能调用外部系统、运行 SQL、生成图表、发送邮件）和自我纠错能力**。它可以在没有人工逐步干预的情况下，自主完成跨系统的长链条端到端工作。

---

### Q6: “什么是 Function Calling（工具调用）？模型为什么不能自己直接调用外部 API？”
> **考查目的**：对大模型本质是概率生成器的清醒认知。

* **核心回答要点**：
  1. **物理本质**：大模型本质是一个基于 Transformer 的自回归概率预测模型，其输入输出全是 Token，其运行在受限的推理显卡集群上，**没有任何网络端口操作权限或操作系统权限**。
  2. **协作流程**：
     - 宿主程序（我们的应用代码）在请求模型时，把一组经过 JSON Schema 规范定义的函数说明（名称、参数类型、使用场景）一同发给模型；
     - 模型理解用户意图后，如果判断需要调用工具，**它不会自己去执行代码，而是停下文本生成，输出符合该格式的结构化参数（JSON）**，并带上标记 `tool_calls`；
     - **真正的执行是由我们的宿主服务（Python/Java后端）在本地或远程发起的**；
     - 执行完毕后，宿主把真实的运行结果（Observation）包装成 `role: tool` 消息写回给模型，模型据此做总结。

---

### Q7: “现在行业内极度推崇的 MCP（Model Context Protocol）协议是什么？它解决了什么痛点？”
> **考查目的**：是否掌握最新技术趋势（Anthropic 开源的行业统一协议）。

* **核心回答要点**：
  * **痛点**：传统模式下，不同框架（LangChain, LlamaIndex, Dify）甚至不同软件（Cursor, Claude, 讯飞平台）各有各的 Tool 定义格式。开发一个数据库查询工具，需要针对每个平台单独写适配代码，形成 $M \times N$ 的重复开发与孤岛生态。
  * **MCP 核心价值**：定义了 AI 时代的**“USB-C 统一接口标准”**。任何 MCP Client（宿主应用）都可以即插即用连接任何由第三方编写的 MCP Server（能力服务）。
  * **核心三要素**：**Resources**（只读数据资产）、**Prompts**（上下文模板）、**Tools**（可执行函数）；支持 `stdio` 本地进程低延迟通道和 `sse` 远程分布式微服务通道。

---

### Q8: “为什么做复杂企业级智能体，业内普遍放弃传统的 LangChain 链式模式，转而拥抱 LangGraph 这种图状态机？”
> **考查目的**：对框架设计哲学的深度理解。

* **核心回答要点**：
  1. **DAG vs 循环图（Cycles）**：传统 LangChain 的核心是 `Chain`，本质是有向无环图（DAG），它只擅长线性的从 A 到 B 的单向流水线。但现实中的复杂 Agent 必须包含**“循环尝试、反思纠偏（Reflection）、条件分支、动态多轮重试”**，用 DAG 表达循环非常痛苦且难以维护；
  2. **显式状态管理（State Management）**：LangGraph 将所有流转基于一个强类型的全局 `State` 和 `Reducers` 归约器，状态清晰透明，告别黑盒；
  3. **天然支持人机协同与中断（Human-in-the-Loop）**：LangGraph 拥有原生的 `Checkpointer` 快照持久化机制，当执行到高危节点时可以主动 `interrupt()` 挂起，等待人工确认后再唤醒继续，还支持时间旅行（Time-Travel）调试。

## 四、 第三部分：工程化落地、可靠性与 Bad Case 排查

### Q9: “在真实业务中，如果大模型输出的 JSON 参数格式损坏或缺失字段导致系统报错，你在工程上怎么防御？”
> **考查目的**：工程抗风险能力与容错设计。

* **标准应答示范（三层防御体系）**：
  > “在生产环境中，我通常构建‘防、检、治’三层防线：
  > 1. **源头防御（约束解码）**：优先使用支持严格结构化输出（OpenAI Structured Outputs）的接口。其底层在解码生成阶段使用上下文无关文法（CFG）对 Token 概率施加 Mask，从物理层面保证 100% 遵循 JSON Schema；
  > 2. **业务校验（Pydantic 拦截）**：在后端使用 Pydantic 模型进行严格的字段、类型、数值范围（如枚举校验、正则匹配）验证；
  > 3. **闭环自修复（Self-Correction）**：如果捕获到 `ValidationError`，**绝不直接崩溃抛错**，而是将具体报错日志（如：`字段 'date' 缺失，且必须符合 YYYY-MM-DD 格式`）包装为系统反馈回灌给模型，触发一次自纠偏重试。根据工程实测，带明确错误提示的重试，二次修复成功率在 90% 以上。”

### Q10: “在多智能体协作（Multi-Agent）中，如果两个 Agent 互相质询，陷入‘死循环和无限踢皮球’，你怎么在架构上解决？”
> **考查目的**：多智能体系统的治理经验。

* **标准应答示范**：
  > “我们在架构上必须设立硬性防线与柔性监督：
  > 1. **硬性配额熔断（Max Turns & Budget Guard）**：在状态图全局配置最大轮次上限（如 `max_iterations = 12`）和单次任务 Token 消耗阈值，一旦触碰硬限制强制抛出中断；
  > 2. **中心化仲裁（Supervisor 拓扑）**：禁止 Agent 之间进行无序点对点的自由广播，所有跨角色协同必须经过中心化的 Supervisor（主管智能体）进行意图裁决与任务终结判断；
  > 3. **状态指纹去重（Cycle Detection）**：对连续几个步骤的 Agent 核心入参和 State 做特征哈希比对，一旦发现连续 2 轮状态高度相似（语义滞留），触发逻辑震荡告警，并主动降级转为人工审核。”

---

### Q11: “大模型 API 延迟高、Token 成本贵，面对并发业务，你有哪些具体的降本提速优化手段？”
> **考查目的**：降本增效（FinOps）与高并发工程素养。

* **标准应答示范**：
  > “主要从以下四个关键维度进行综合调优：
  > 1. **落地 Prompt Caching（前缀缓存）**：将静态的 System Prompt、工具 Schema、知识库长文档固定在消息前缀，动态输入放尾部。命中 KV Cache 后，计费通常直降 50%~80%，且首字生成时间（TTFT）大幅缩短；
  > 2. **动态意图分级路由（Model Cascading）**：绝不全量无脑调用高昂的旗舰模型。先用轻量低成本小模型（如 Spark-Lite / GPT-4o-mini）做意图分类、Query 改写和字段提取；只有当任务判定为深度长程规划时，才动态路由到顶级模型；
  > 3. **上下文剪枝与动态摘要**：对于历史对话，超过阈值后自动增量压缩为 Summary；对于工具返回的大段原始数据（如几万字的爬虫 HTML），在后端先过滤出核心字段再送入模型；
  > 4. **流式 SSE 与异步并发**：全面采用异步架构（`asyncio`），对可解耦的任务采用并发分治（Fan-Out/Fan-In），并通过 SSE 提升端侧感官流畅度。”

### Q12: “你平时是如何向业务方证明智能体系统是可靠的？你们的自动化评测（Eval）体系怎么建的？”
> **考查目的**：是否有严谨的工程度量思维，是否懂 Ragas 和 LLM-as-a-Judge。

* **标准应答示范**：
  > “在工业界，脱离量化指标的‘人工肉眼抽查’是无法支撑生产迭代的。我们建立了双重评测基准：
  > 1. **RAG 检索增强专项评测（基于 Ragas 框架）**：
  >    - **Faithfulness（忠实度 / 无幻觉率）**：衡量模型生成的每个结论是否有检索文档作为事实依据；
  >    - **Answer Relevance（答案相关性）**：衡量回答是否切题；
  >    - **Context Precision & Recall**：衡量检索出的文档是否有高精度的排名和召回率；
  > 2. **Agent 决策轨迹评测（Trajectory Eval）**：
  >    - 核心监控：**工具选择准确率（Tool Selection Accuracy）**、**参数合规率**、**长链路任务完成率（Success Rate）** 和 **平均解决步数（Step Count）**；
  > 3. **流水线化回归测试**：
  >    - 沉淀包含 200~300 个典型业务 Case（包含历史 Bad Case）的黄金测试集（Golden Dataset）；
  >    - 任何 Prompt 或代码迭代发版前，在 CI/CD 中通过 **LLM-as-a-Judge** 结合打分量表（Rubrics）自动跑分，确保核心指标没有出现向后退化（Regression）才允许上线。”

### Q13: “请分享一个你在 Agent 开发中遇到过的最棘手的 Bad Case，排查思路和解决过程是怎样的？”
> **考查目的**：极度高频且关键的实战排查题，考验真实项目经验。

* **标准应答模板（STAR 原则，可直接套用）**：
  > * **背景（Situation）**：在开发一个企业财务与合同比对分析 Agent 时，用户上传扫描件 PDF 研报，要求计算‘某业务板块的毛利率同比增速’。
  > * **问题（Task/Bad Case）**：模型在最后一步给出的答案完全算反了，且在回复中表现得非常自信（严重幻觉）。
  > * **排查过程（Action）**：
  >   1. 我首先调取 **Langfuse 链路追踪日志**，逐步拆解 Trace，排除了 Python 代码沙箱计算函数的错误（计算逻辑正确）；
  >   2. 进一步查看上游 RAG 检索节点的 Span，发现原始 PDF 是跨页三栏复杂排版，朴素的分块算法直接把表头和第二页的数据行截断分开了；
  >   3. 向量检索虽然召回了包含该数字的片段，但因为失去了表头‘2024年’与‘2025年’的列定义，大模型在没有坐标语境的情况下，把两年的数值张冠李戴了。
  > * **解决措施（Result）**：
  >   1. **数据源头重构**：将粗暴分块换成了版面分析工具（MinerU/Docling），把跨页表格整体提取为完整的 Markdown Table 语法；
  >   2. **上下文增强检索**：引入 Anthropic 的 Contextual Retrieval 策略，在表格切片前由小模型自动生成 50 字的表格所属章节与年份背景说明；
  >   3. **增加 Cross-Encoder 深度重排**。
  >   * **最终成效**：重测后该类跨页复杂表格问答的数值准确率从原来的 52% 跃升到了 94% 以上，该 Bad Case 也被我沉淀进了团队的日常自动化回归评测集中。”

## 五、 第四部分：结合科大讯飞业务的场景构想（极大加分项）

### Q14: “如果让你结合科大讯飞现有的核心业务（如智能办公本/听见会议），设计一个高价值的 Agent，你会怎么构思？”

* **高分架构构思方案**：
  > **项目构想**：**“基于讯飞听见/办公本的‘会后自主行动闭环 Agent’（Meeting Action Agent）”**
  > 
  > * **现状痛点**：目前大部分会议总结工具只停留在“生成文本纪要、待办事项列表”，用户开完会依然需要手动去发邮件、去 Jira 提单、去日历排期，并没有真正解放生产力。
  > * **Agent 闭环架构**：
  >   1. **输入感知**：接入讯飞听见的实时转写文本流与声纹说话人分离数据；
  >   2. **任务解构（LangGraph 编排）**：Agent 实时识别对话中具有强行动属性的决议（例如：‘李工这周五前输出架构设计文档，张总下周二组织评审’）；
  >   3. **工具与系统联动（MCP 协议对接企业系统）**：
  >      - 调用 Calendar MCP：自动在与会人员的企业日历上预约“下周二评审会”；
  >      - 调用 Issue Tracker MCP：在 Jira/TAPD 自动创建待办任务并 @ 对应负责人；
  >      - 调用 Mail MCP：草拟规范的会议纪要邮件；
  >   4. **人机在环审批（Human-in-the-Loop）**：在智能办公本屏幕上弹出一键确认卡片，参会主持只需要轻点一下“确认派发”，Agent 即可在后台并发完成所有企业内部系统的流转。
  > * **商业价值**：让讯飞办公产品从单一的‘记录工具’升级为‘端到端数字秘书行动中枢’，客户粘性与续费率将产生质的提升。”

## 六、 第五部分：反问面试官环节（留给候选人的高水平提问清单）

在面试最后，面试官或 HR 通常会问：“你有什么想了解或者问我的吗？”  
**切忌回答“没有了”**。提出有深度的问题能够让对方感受到你对团队和业务的认真：

### 推荐向 HR / 技术负责人提问的高价值问题：
1. **关于业务侧重点**：
   * *“请问咱们团队目前在智能体方向，业务重心主要是在企业级定制化数字员工（B端/政企落地），还是偏向与讯飞硬件及办公平台（C端/轻量Agent）进行深度集成？”*
2. **关于技术栈与基座**：
   * *“目前咱们团队在搭建复杂智能体应用时，底层调度是主要基于自研的智能体编排引擎，还是会融合 LangGraph 等现代状态机框架？团队对于最新 MCP 这类开放协议在内部的规划是怎样的？”*
3. **关于面临的工程挑战**：
   * *“以团队目前的经验来看，当前将星火大模型与 Agent 结合推进到客户真实业务中时，团队认为面临最大的工程挑战主要集中在幻觉治理、私有化环境适配，还是垂直领域的深度规划能力上？”*
4. **关于团队与期望**：
   * *“如果我有幸加入团队，您期望我在入职前 3~6 个月内在团队中发挥的最关键作用或解决的核心痛点会是什么？”*
