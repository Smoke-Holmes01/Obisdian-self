# 个人知识库 (Obsidian Vault) 写作与组织规范

欢迎使用个人知识库。本知识库用于系统化整理考研 408 备考、操作系统（OS）知识、版本控制（Git）工具链以及个人学习计划。

为保持知识库的整洁性、可检索性与美观度，所有笔记在创建或修改时均需遵循本规范。

---

## 🗺 知识库整体结构

知识库通过 **MOC (Map of Content，内容地图)** 机制进行组织，形成“根目录索引 -> 主题索引 -> 具体笔记”的网状链接结构。

```text
c:\StudyFiles\Notes\smk
├── .agents/                 # 智能代理配置与工具
├── .obsidian/               # Obsidian 配置文件
├── Git/                     # Git & GitHub 主题
│   └── Git MOC.md           # Git 主题索引
├── OS/                      # 操作系统主题 (CentOS/Ubuntu/Windows)
│   └── OS MOC.md            # OS 主题索引
├── Plan/                    # 学习计划与备考路线图
│   └── Plan MOC.md          # 计划主题索引
├── 考研408/                 # 考研 408 备考主题 (数学/专业课等)
│   └── 考研408 MOC.md       # 408 备考主页
├── MOC.md                   # 知识库内容地图 (Root MOC)
└── README.md                # 本规范文档
```

## 1. 元数据规范 (YAML Frontmatter)

每篇笔记的开头**必须**包含 YAML Frontmatter 元数据块。格式如下：

```yaml
---
title: "笔记的标题"
created: 2026-07-20 18:45
updated: 2026-07-20 18:45
tags:
  - 学科/主题/子话题
category: "预设分类"
status: "draft | active | completed"
---
```

### 字段填报要求
1. **`title`**：必须与文件名完全一致，使用双引号包裹。
2. **`created` & `updated`**：时间格式统一为本地 24 小时制 `YYYY-MM-DD HH:mm`。
3. **`tags`**：**强制使用多级嵌套标签**。严禁使用扁平标签。
   - *正确示例*：`考研408/数学/高等数学/等价无穷小`，`OS/CentOS7/Terminal`
   - *错误示例*：`数学`, `高数`, `CentOS7`
4. **`category`**：必须从以下四种预设分类中选择其一：
   - `"技术文档"`：适用于命令速查、软件配置、环境搭建等。
   - `"概念定理/公式总结"`：适用于数学公式、学科核心概念、考试考点等。
   - `"索引导航"`：适用于 MOC 索引页。
   - `"学习计划"`：适用于复习规划、里程碑、备考路线图等。
5. **`status`**：反映笔记的当前完善状态：
   - `draft`：草稿，包含快速记录的零碎想法或不完整的笔记。
   - `active`：正在完善/持续更新中的笔记。
   - `completed`：内容已整理完毕、格式规范的最终笔记。

## 2. 知识关联与导航

为避免出现“孤岛笔记”，每篇笔记都必须参与到知识网中：

* **返回导航 (MOC Link)**：在元数据下方（或笔记最底部）**必须**提供一个指向其直属父级 MOC 索引页的返回链接。
  - *示例*：`[[../OS MOC|← 返回 操作系统 MOC]]`
* **概念双链 (Inline Links)**：当笔记中提及其他已有的概念或笔记时，使用 `[[链接笔记|自定义标签]]` 进行双向关联。
  - *示例*：如要提到泰勒展开，可使用 `根据 [[常用函数的泰勒展开式|泰勒展开公式]] 计算...`

## 3. 排版美化与视觉规范

优秀的视觉排版能大幅提升复习和阅读的体验。

### 3.1 严格的标题层级
- 笔记首个标题**必须**是使用单个 `#` 的 H1 标题，且内容与文件名（即 YAML 的 `title`）完全一致。
- 之后的子章节严格按 `##`、`###`、`####` 递减。
- **禁止跨越标题级次**（例如：不能从 `#` 直接跳到 `###`）。

### 3.2 重点词汇高亮
- 核心概念、专业术语或关键定理在正文中**首次出现**时，必须使用 **粗体** (`**关键字**`) 进行标记。

### 3.3 Obsidian 专属 Callout 框
对于重点、警示、例题等特殊内容，必须使用 Obsidian 提供的 Callout 块进行包装：

```markdown
> [!note] 
> 用于补充背景信息、说明或一般说明。

> [!tip] 
> 用于提示小技巧、复习建议或高效解法。

> [!important] 
> 用于标识考试重点、核心要点。

> [!warning] 
> 用于提示易错点、高频陷阱、边界条件。

> [!example] 
> 用于包裹例题、证明步骤、代码片段或实操案例。
```

## 4. 数学公式与图表

### 4.1 数学公式 (LaTeX)
所有数学公式必须使用 LaTeX 规范渲染，保证排版专业度。
* **行内公式**：使用单个 `$` 符号。如 `$E = mc^2$` 渲染为 $E = mc^2$。
* **独占行公式**：使用双 `$$` 符号。
  - *示例*：
    ```markdown
    $$\lim_{x \to 0} \frac{\sin x}{x} = 1$$
    ```
    渲染为：
    $$\lim_{x \to 0} \frac{\sin x}{x} = 1$$

### 4.2 流程图与架构图 (Mermaid)
对于包含步骤、逻辑分支或系统架构的内容，使用 `mermaid` 块进行可视化展示。
* *示例*：
  ```markdown
  ```mermaid
  graph TD
      A[输入数据] --> B{判断条件}
      B -- Yes --> C[处理逻辑 A]
      B -- No --> D[处理逻辑 B]
  ```
  ```
